公式ドキュメントの実行確認

「安定性の問題を修正する」で何が直るのか

対象は Fix stability issues です。確認するのはクラッシュではなく、親が再 compose したとき、入力が同じなら子を skip できるかです。

公式の問題 なぜ List は Unstable 3 つの直し方 アプリでの見方

公式が直したいこと

Compose は、引数が Stable で前回と同じなら子 Composable を skip（再実行しない）できます。 List は Unstable なので、親が何か別の理由で再 compose すると、リストの中身が同じでも子が毎回走ります。遅い、が問題です。

なぜ要素が Stable でも List は Unstable か

診断ページの例は val set: Set = mutableSetOf("foo") です。 変数の型は読み取り専用に見えますが、箱の実体は可変です。コンパイラは宣言型しか見ないので、 List / Set / Map を Unstable にします。

StableItem

公式の Snack。val だけなので Stable。ここは問題ではない。

List<StableItem>

入れ物がインタフェース。要素が Stable でもパラメータは Unstable。

公式が出している直し方

ドキュメントの順です。アプリも同じ 3 つを並べています。

  1. Strong Skipping — Unstable 引数でも skippable にするコンパイラモード。Kotlin 2.0.20 からデフォルトオン。このプロジェクトは 2.0.0 なので、-Pcompose.strongSkipping=true で確認する。
  2. kotlinx ImmutableList — 本当に不変なコレクション。コンパイラが Stable と認識する。
  3. @Immutable で包む — data class Holder(val items: List<...>) にアノテーションを付け、List を不変として扱う約束をする。
Composable Strong Skipping OFF ON
HighlightedSnacks(List) 回数増える（公式の問題） 同じインスタンスなら増えない（公式の最初の修正）
HighlightedImmutableSnacks(ImmutableList) 増えない 増えない
HighlightedSnackCollection(@Immutable) 増えない 増えない
成功条件は「親の tick だけ増えて、skip された子の compose 回数が止まっている」ことです。画面の表示テキストが変わる必要はありません。

アプリでの手順

  1. メイン画面 →「安定性の問題を修正する」
  2. Strong Skipping が OFF であることを確認
  3. 「親だけ再 compose」を何度か押す
  4. HighlightedSnacks の回数だけ増え、下の 2 つは増えないことを見る
  5. レポート: ./gradlew :feature:liststability:compileDebugKotlin
  6. オプション: -Pcompose.strongSkipping=true で入れ直すと、List 側も回数が止まる
./gradlew :app:assembleDebug
./gradlew :app:assembleDebug -Pcompose.strongSkipping=true
この検証ではリストを破壊的に変更しません。MutableList の共有による例外や古い UI は、公式ページの主題ではないため画面から外しています。
